## Deferred from: code review of 2-1-criacao-de-sessao-com-bloqueio-de-conflito-de-horario (2026-08-10)

- **`idx_sessoes_sala_id` redundante** — a V3 criou `idx_sessoes_sala_id_data_hora`, do qual `idx_sessoes_sala_id` (V1) é prefixo. O índice simples agora só custa escrita e espaço. Precisa de uma migration própria de `DROP INDEX`; escopo fora desta story. Reavaliar junto da Story 2.3, que revisita índices de listagem pública.
- **`"LIVRE"` como string literal** — `SessaoService.java:87` duplica em código o `CHECK (status IN ('LIVRE','RESERVADO','VENDIDO'))` de `V1__schema.sql`, sem enum nem constante. Um typo só falha em runtime, como `DataIntegrityViolationException` → 500. Toda a Epic 3 (reservas) vai reusar esses valores — introduzir o enum lá, onde o conjunto completo de transições fica visível.
- **Duas gerações de Jackson convivendo** — `RestAccessDeniedHandler` importa `tools.jackson.databind.ObjectMapper` (Jackson 3, default do Spring Boot 4) enquanto `TmdbClient` importa `com.fasterxml.jackson.annotation.JsonProperty` (Jackson 2). Funciona hoje porque Jackson 3 ainda honra as anotações da 2, mas é armadilha silenciosa pra quem for adicionar serialização customizada. Pré-existente da Story 1.2.
- **Nenhuma guarda de rota no front-end** — `/organizador`, `/organizador/sessoes/nova`, `/cliente` e `/portaria` renderizam pra qualquer visitante (`web/src/App.tsx`). Não é falha de segurança (a autorização é checada no back a cada request), mas um CLIENTE logado preenche o formulário inteiro de criação de sessão antes de tomar 403, e um visitante sem token recebe a mensagem genérica "Erro ao comunicar com o servidor". Padrão pré-existente desde a Story 1.1 — resolver de uma vez com um componente de rota protegida.
- **Invariante de não-sobreposição não declarativa no banco** — a garantia de que duas sessões não coexistem sobrepostas na mesma sala vive só no par `findByIdForUpdate` + `existeConflitante` dentro de `SessaoService.criar`. Decisão do code review da Story 2.1: manter só o lock pessimista, que já é mecanismo de banco e cumpre o non-negotiable do CLAUDE.md — a alternativa (`EXCLUDE USING gist` + `btree_gist` numa V4) acoplaria o buffer de 4h ao schema, onde hoje ele é uma constante única no service. **Ação obrigatória na Story 2.2** (edição de sessão): o `PUT` precisa replicar o mesmo par lock+checagem, senão produz sobreposição sem o banco reclamar.
